# Finish P0 (Ticket Resolver) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every must-pass Ticket Resolver scenario (TR-01, 03, 05, 06, 10, 11, 12, 13) passes `check.py` on a live run,
the nice-to-haves (TR-02, 04, 07, 09, 14) have been attempted, and the README shows the real scorecard.

**Architecture:** Nothing new gets built. Each task runs one scenario end to end with `scripts/score.sh` (reset the fork
→ orchestrator in script mode → `check.py`), reads the failing checks, fixes the root cause in the one component that
owns it (skill, scorer, orchestrator or scenario file) with a unit test where the fix is code, re-runs, and records the
result. Scenarios run **one at a time**: they share the fork `vishnuverse/humanize`.

**Tech Stack:** TrueForge 0.2.1 (local, `http://localhost:8790`), agent `ticket-resolver` on
`openrouter/deepseek-v4-flash` (0423), TypeScript orchestrator (`orchestrator/`), Python scorer (`scripts/check.py`,
`scripts/shipgate_check/`), bash (`scripts/score.sh`, `scripts/reset.sh`).

**Spec:** `docs/SPEC.md` §4 (flow T1–T15, evidence check, push-back, HITL protocol, scenario table §4.7) and
`docs/contracts.md` (run directory, approval record, scenario YAML).

## Global Constraints

- One scenario at a time; never two agent runs against the fork concurrently.
- Always run through `scripts/score.sh <ID>` with `.env` exported: `set -a && . ./.env && set +a && bash scripts/score.sh <ID>`.
  Never run `scripts/reset.sh --yes` by hand except to recover a broken fixture state.
- Agent model stays `openrouter/deepseek-v4-flash` with `reasoning_effort: high`, `temperature: 1.0`, `top_p: 0.95`,
  `max_tokens: 32768` (`docs/model-bakeoff.md`). Budget: OpenRouter key hard limit $5 (spent ≈ $0.07 at plan time).
- After any change to `skills/ticket-resolver/SKILL.md` or `agents/ticket-resolver.json`, re-register:
  `npx --yes tsx scripts/setup_agents.ts --inline-skill`.
- Before every commit: `uv run pytest tests/check -q`, `uv run ruff check scripts tests`,
  `uv run ruff format --check scripts tests`, `npm --prefix orchestrator test`, `npm --prefix orchestrator run typecheck`.
- Never weaken a check to make a scenario pass unless the check contradicts `docs/SPEC.md`; if it does, fix the
  scenario file and say so in the commit message.
- Record every scenario result (pass count, run dir, cost, root causes) in `docs/MEMORY.md` and `docs/HANDOVER.md`.
- Conventional commits, each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

  (`no_existing_test_modified` must PASS).

  Owner: Task 7.
- **Clock-dependent fixture** (TR-04): #4 only shows while the machine's local date differs from UTC (IST before
  05:30, or `TZ=Pacific/Honolulu` / `Pacific/Kiritimati` at other hours). Owner: Task 9 (run it before 05:30 IST).

## How to run and triage one scenario (used by every task)

Run (≈ 6–8 minutes, ≈ $0.01):
```bash
cd trueforge-shipgate  # your clone
set -a && . ./.env && set +a && bash scripts/score.sh <ID> 2>&1 | tee /tmp/score-<ID>.log
```
Result line: `# RESULT <ID> PASS|FAIL (n passed, m failed, k skipped)`. The run directory is printed after
`completed (exit N) ·`. The session page is `http://localhost:8790/sessions/<session id>`.

Triage each `FAIL` line to one owner, then fix only there:

| Symptom | Owner | Fix pattern |
| --- | --- | --- |
| Agent did the wrong thing (skipped a step, wrong outcome, extra write) | `skills/ticket-resolver/SKILL.md` | Tighten the rule where it lives (hard rule, procedure step or push-back row); re-register; re-run |
| Agent did the right thing but a check says FAIL | `scripts/shipgate_check/` or the scenario YAML | Add a failing unit test in `tests/check/test_check.py` reproducing the false FAIL, fix, test green |
| Gate answered wrongly / run dir incomplete / labels wrong | `orchestrator/src/` | Add a failing test in `orchestrator/test/`, fix, tests + typecheck green |
| 403/429/5xx, SSL, network | environment | Fix config (token scope, provider, sandbox env); never code around it in the skill |

Read the agent's own view of the run when the cause isn't obvious:
```bash
R=$(ls -td runs/<ID>/*/ | head -1)
python3 -c "
import json,sys
for x in json.load(open('$R/events.json')):
    e=x['event']
    if e['type']=='model.message' and (e.get('content') or '').strip(): print('MSG', e['content'][:300].replace(chr(10),' '))
    if e['type']=='tool.approval_required': print('GATE', e['tool_calls'])
"
```
